# 光模块读写码上位机 Demo —— 使用说明

这套代码的作用：让你在**没有测试板、没有光模块**的情况下，做出一个能跑、能演示、能被面试官追问两层的作品。
它对应你面试时唯一需要讲清楚的那条链路：**上位机界面 → 通信协议 → 模块寄存器读写 → 数据落盘/报表**。

设计思路：整个 Demo 是两个角色跑在一个程序里。

- **上位机（真实你要写的代码）**：WinForm 界面 + 帧协议打包 + 流式解析（处理粘包/半包）+ 超时重发 + DDM 换算 + CSV 导出
- **下位机（模拟出来的）**：一块 256 字节的 EEPROM，按 SFF-8472 的思路分成 A0h 身份信息区和 A2h 诊断区，带写保护、解锁密码、实时读数漂移

真实项目里，PC 走 USB/串口/网口把帧发给测试板，板上的 MCU 才去产生 I2C 时序。**上位机侧永远只是在处理"帧"**，所以这个模拟是符合真实结构的，不是自己骗自己。

## 一、环境准备（Windows）

1. 装 **Visual Studio 2022 Community**（免费），安装时勾选工作负载：**.NET 桌面开发**
2. 装 **.NET 8 SDK**（VS 安装器里勾 ".NET 8 SDK"，或单独下载）
3. 不需要 Arduino、不需要买板卡、不需要装串口驱动

> 只用 VS Code 打不开 WinForm 设计器，也别用老版 VS2019（默认没 .NET 8 模板）。

## 二、打开工程的两种方式

**方式 A（推荐，最省事）**：把整个 `光模块上位机Demo` 文件夹放到你的电脑上（比如 `D:\demo\`），双击里面的 `OpticalModuleDemo.csproj`，VS 会自动打开→右上角绿色三角运行。

**方式 B（更保险，练一次新建项目）**：

1. VS → 新建项目 → 搜 **Windows 窗体应用** → 选 **C# / Windows Forms App**（不要选 ".NET Framework" 那个，选带 ".NET" 字样的）→ 项目名称 `OpticalModuleDemo` → 创建 → 框架选 **.NET 8**
2. 在右侧解决方案资源管理器里 **删除** 自动生成的 `Form1.cs` 和 `Form1.Designer.cs`
3. 右键项目 → 添加 → 现有项 → 把我这几个 `.cs` 文件全选上（**`SerialTransport.cs` 先不要加**，那是阶段二的）
4. 删掉自动生成的 `Form1.cs` 后如果 `Program.cs` 报红，用我这份 `Program.cs` 覆盖它
5. F5 运行

## 三、文件清单（按阅读顺序）

| 文件 | 内容 | 面试要讲的点 |
| --- | --- | --- |
| `Proto.cs` | 帧格式定义、CRC-16/CCITT、**FrameParser 流式解析器** | 粘包/半包怎么解决、校验失败怎么重同步 |
| `Transport.cs` | 传输通道抽象 `ITransport`、模拟光模块 `SimulatedModule`、内置模拟板卡 `SimTransport`（含三个故障注入开关） | 上位机为什么不碰 I2C 时序、写保护/解锁、DDM 编码值换算 |
| `BoardClient.cs` | 一条在途请求 + 超时重发 + 分帧连续读写 | 通信层为什么要和界面层分开、超时后怎么办 |
| `MainForm.cs` | 界面、事件处理、`async/await`、`Invoke` 跨线程更新、CSV 导出 | 界面为什么不会卡死、跨线程为什么必须 Invoke |
| `Program.cs` / `csproj` | 入口与工程文件 | — |
| `SerialTransport.cs` | 真实串口实现（阶段二） | 串口占用、异常释放 |

**帧格式**（`Proto.cs` 顶部注释有完整说明）：

```
AA 55 | CMD | DEV/STATUS | PAGE | OFFSET | LEN | DATA[LEN] | CRC_H CRC_L
```

整帧长度 = 7 + LEN + 2；CRC 覆盖从帧头到 DATA 结尾。请求帧和应答帧**结构完全同构**，所以解析器只需要写一份——这也是真实项目里的常见做法。

## 四、验收清单（照这个顺序做，每步都要看到预期现象）

| # | 你做什么 | 应该看到 | 这一步证明你会了什么 |
| --- | --- | --- | --- |
| 1 | 点【连接板卡】 | 日志出现 `-> 发帧 CMD=0x05 ...`，然后 `<- 收帧`，状态变绿色"已连接"，显示 `SIM-BOARD-1.0` | 会握手/心跳，等价于仪器控制的 `*IDN?` |
| 2 | 点【读码】 | 日志连发 4 帧（每帧要 32 字节），界面上自动填出厂商名 `DEMO-FIBER`、料号、序列号等 | 连续读要分帧，知道"单帧数据长度有上限" |
| 3 | 直接点【写码并校验】（先不解锁） | 日志出现 **`写码被拒绝：写保护生效（只读区/未解锁）`** | 知道写码不是想写就能写，这是产线最在意的点 |
| 4 | 点【① 先解锁】，再点【写码并校验】 | 逐段写入 → 自动回读 → 每个字段打印"校验一致"，最后一行 `写码校验通过` | 写完必须回读逐字节比对，这是写码软件的必备流程 |
| 5 | 把厂商名改成 20 个字符再写 | 被截断到 16 字节（协议长度限制），回读仍一致 | 定长字段编码（截断/补空格） |
| 6 | 点【启动轮询】，同时拖动、点击窗口 | 温度/电压/光功率每 0.5 秒刷新，**窗口完全不卡**；偶尔温度变红 | 后台线程通信 + `Invoke` 更新 UI；阈值判定 |
| 7 | 勾【注入半包】→ 再点读码 | 日志出现 `收到 N 字节但凑不出完整帧（半包/脏数据），继续等待`，但最终结果正确 | 帧解析器真的在处理半包，不是假设一次到位 |
| 8 | 勾【注入脏字节】→ 点读码 | 日志有"重同步丢弃 N 字节"，统计栏数字增加，功能正常 | 抗噪声、能从错乱字节流里重新找到帧头 |
| 9 | 勾【注入丢帧】→ 多点几次读码/写码 | 日志出现 `等待应答超时(1000ms)，已重试 1/3`，多数情况下重试后成功 | 超时重发；也体验了"偶尔真会失败"，产线要能报警 |
| 10 | 轮询 30 秒后点【停止】→ 点【导出测试数据 CSV】 | 得到一份 CSV，Excel 打开中文表头不乱码 | 测试数据落盘、报表输出 |

**做完 10 步，你就有了三段可以讲 5 分钟的项目故事**：帧协议与粘包处理、写保护与解锁回读校验、后台通信不卡界面 + 超时重发。

## 五、常见报错与解决

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 编译报 `The type or namespace name 'Ports' does not exist` | 把 `SerialTransport.cs` 加进项目了但没装 NuGet 包 | 先不加这个文件（阶段一不需要），或安装 `System.IO.Ports` |
| 报 `Form1` 相关错误 | 新建项目后没删掉模板生成的 Form1 | 删掉 `Form1.cs` / `Form1.Designer.cs`，用我给的 `Program.cs` 覆盖 |
| 运行时报"跨线程操作无效：控制从一个线程访问…" | 你改了代码，在后台线程里直接给控件赋值 | 更新界面必须走 `Ui(delegate { ... })`，里面用 `Invoke/BeginInvoke` |
| 中文显示成方块 | 字体不支持 | 窗体 `Font` 用 `Microsoft YaHei UI`（代码里已设） |
| 界面点了没反应 | 忘了先点【连接板卡】 | 日志会提示"请先点【连接板卡】" |
| CSV 打开乱码 | 编码问题 | 代码已用带 BOM 的 UTF-8，别改成 ANSI |

## 六、后面两个阶段（不用全做，按面试时间安排）

**阶段二 · 换成真串口（1 天，价值最高）**

1. 装 **com0com**（开源，建一对虚拟串口，比如 COM3↔COM4）
2. 按 `SerialTransport.cs` 文件头注释启用它
3. 再写一个 30 行的小控制台程序：打开 COM3，把收到的字节原样写回 COM4（回环）
4. 上位机连 COM4 → 走的是真实的串口 API、真实的 `SerialPort.DataReceived` 线程

到这一步，你可以理直气壮地说"我用 `SerialPort` 做过串口通信"。

**阶段三 · 加数据库与文档（2 天，对应 JD 第 1、5 条）**

- 装 NuGet：`MySqlConnector` + `Dapper`，建表 `test_record(sn, type, time, temp, vcc, tx_dbm, rx_dbm, bias_ma, result)`，轮询数据入库，写码记录入库，界面加一个"按 SN 查历史"的输入框
- 写一份 3 页的《软件设计说明》：模块划分、帧协议定义（表格）、状态与错误码、异常处理策略、测试用例清单。**JD 两次要求"输出设计报告"，这份文档比代码更能证明你能交付**

## 七、面试怎么讲这个 Demo（直接背）

**一句话定位**
> 我自己写了一个光模块读写码上位机原型：WinForm 界面 + 自定义帧协议 + 模拟下位机联调，实现了读码、解锁写码、回读校验、DDM 实时采集与报表导出。

**被追问"没有板卡你怎么测的"**
> 我查了资料，真实链路是 PC 通过 USB 或串口连测试板，板上的 MCU 去产生 I2C 时序访问模块的 EEPROM，上位机侧处理的其实是一帧帧自定义报文，并不直接碰 I2C。所以我把测试板和模块一起模拟了：内部两块 256 字节区域，A0h 放身份信息、A2h 放诊断数据，支持分页、写保护和解锁，还能注入半包、脏字节和丢帧来验证我的解析与超时重发逻辑。接真实板卡只需要把内置通道换成 `SerialPort` 实现，通信层和界面层代码不用动。

**被追问"最难的地方是什么"**
> 帧的边界。串口一次到达的字节不保证等于一帧，可能半帧也可能两帧粘一起。我的做法是字节先进缓冲区，先定位帧头，再按长度字段判断整帧是否收齐，收齐才校验 CRC 取出来；校验失败就丢帧头重同步，上层靠超时重发兜底。我用故障注入验证过：打开半包和脏字节开关后，统计栏能看到丢弃的字节数在增加，但读码结果依然正确。

**被追问"你哪里还不熟"（一定会有）**
> 真实仪器（误码仪、光功率计）我没操作过，SCPI 和 VISA 只看了资料；CMIS 的分页和 CDB 命令也还没实践。这两块我理解原理，缺的是上手环境。

诚实交代短板比硬撑强得多——前面这几段话你只要真的做完了 Demo，说出来是自然的。

## 八、这份代码里必须你自己核对的地方（重要）

我不能保证所有偏移和单位跟你将来要用的模块一致，所以下面这些我在代码里都加了注释标记：

1. **A0h 字段偏移**（厂商名 20、OUI 36、料号 40、Rev 56、SN 60、日期码 70）：采用业内常见布局。**请下载 SFF-8472 原文的 Memory Map 章节逐条核对**，不同封装/厂商有差异。
2. **A2h 实时量的标度**（温度 1/256℃ 带符号、电压 100µV、电流 2µA、光功率 0.1µW）：同上，务必以规范为准；我特意保留了"带符号 16 位"这个最容易写错的点。
3. **告警阈值的存放位置**：Demo 简化成 A2h 偏移 0~9 的连续排布，真实规范里每类量的单位与位置不同。
4. **解锁密码区**：SFF-8472 并没有统一规定密码怎么放，各厂商自己实现（所以 Demo 用自定义密码 `01 02 … 08`）。这一条正好是你可以跟面试官说"我注意到这块各家不一样"的细节。

**核对规范原文这个动作本身，就是这个岗位的日常工作内容**，做完记得在面试里提一句。

## 九、按天推进（每天 3 小时，7 天版）

| 天 | 做什么 | 完成标准 |
